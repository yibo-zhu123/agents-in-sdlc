Copilot をエージェントモードにすると、コードベースを調査し、変更を提案してファイルを編集し、コマンドを実行します。VS Code の Copilot Chat では、自分のマシン上で作業する Copilot のツール呼び出しやファイル編集をリアルタイムに確認できます。差分をインラインでレビューして個々の変更を採用または取り消し、エディターを離れずに追加のプロンプトを送って作業を調整できます。

この演習では、次の作業を行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集をレビューして採用します。
- セッションの途中でエージェントに指示し、ハイコントラストモードにライトモードのトグルを追加します。

## シナリオ

[演習 4][previous-lesson]で使用したアクセシビリティのカスタムエージェントは、ハイコントラストモードを実装中です。作業中にデザインチームから新しい依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードのトグルも追加します。新しい会話を最初から始める代わりに、既存のセッションに指示を送り、作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが実行する手順が表示されます。調査したファイル、実行したコマンド、提案した編集などを確認できます。各ファイルの編集は差分と **Keep** / **Undo** 操作とともにインラインで表示されます。

1. 演習 4 で使用した Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールして、ツール呼び出しを確認します。ファイルの読み取りと編集、エージェントが実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - **Keep** を選択して変更を採用します。
    - **Undo** を選択して変更を取り消し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開いて、このセッションでエージェントが変更した作業セット全体を確認することもできます。

> [!NOTE]
> ツール呼び出し (たとえばターミナルコマンドの実行) に許可が必要な場合、エージェントは一時停止して **Allow** の確認を表示します。内容を確認し、許可するコマンドを選んでください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に変更内容をまとめたメッセージが表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードが完成したら、同じ会話にライトモードのトグルを追加します。同じチャットセッションを続けるため、エージェントは前の作業で編集したコンポーネント、スタイルの方法、local storage の使い方などのコンテキストを保持しています。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントが既存の変更を調べ、ライトモードの追加を提案する様子を確認します。
3. ハイコントラストモードの場合と同じように、提案された編集をレビューし、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントの進め方が意図と異なる場合 (たとえばトグル UI の望まないリファクタリングを試みる場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の説明を送ります。

> [!TIP]
> セッションを最初から始めるより、進行中のエージェントに指示を送る方が効率的です。追加プロンプトを使って調整できます (たとえば「CSS を簡潔にし、セレクターを重複させず CSS 変数を使ってください」)、方向を修正できます (「トグルを 3 つに分けず、ライトモードを既存の設定パネルに追加してください」)、範囲を広げられます (「両方のトグルにキーボードショートカットも追加してください」)。

## 作業セットをレビューする

変更をコミットする前に、エージェントが編集したすべてのファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧全体を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更ファイルをいくつか開き、差分を確認します。カスタムエージェントが示したアクセシビリティのパターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage への保存など) が使われていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次の[レッスン][next-lesson]でブランチを公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードを使って、セッションの進行を監視し、方向付けました。ファイルの編集をレビューしながら採用または取り消しを選び、追加の依頼を送ってコンテキストを保ったまま作業を拡張しました。

このレッスンでは、次の作業を行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を採用または取り消しました。
- 追加のプロンプトを使い、セッションの途中で作業を方向付けました。
